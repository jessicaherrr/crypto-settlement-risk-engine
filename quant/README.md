# askgene_quant

Python quantitative risk engine for the Crypto Settlement Risk Engine.

- `config.py` — shared defaults (fitting-window length, refit frequency,
  EWMA decay, annualization convention)
- `data/` — Coinbase Exchange market-data fetching with a local parquet
  cache (`loader.py`, `coinbase.py`), data-quality checks (`quality.py`),
  log-return construction (`returns.py`)
- `volatility/` — rolling/realized volatility (`realized.py`), EWMA
  (`ewma.py`), GARCH(1,1) with parameter estimation and conditional-variance
  updating deliberately separated (`garch.py`)
- `models/` — `ModelState` (the serializable record of a fitted model:
  params, training window, fit diagnostics, latest conditional variance),
  JSON persistence (`store.py`), and the online fit/update/refit pipeline
  (`pipeline.py`)
- `validation/` — RMSE/QLIKE (`metrics.py`) and a look-ahead-free
  walk-forward comparison of all three volatility models (`backtest.py`)
- `simulation/`, `risk/`, `policy/`, `quotes/`: return-distribution
  scenarios (historical / filtered-historical / GBM), VaR/Expected
  Shortfall, stress testing, a collateral policy, and the `RiskQuote`
  representation with deterministic fixed-point serialization
- `signing/`: EIP-712 domain/struct encoding and the
  `RiskOracleSigner` that turns a `RiskQuote` into the signature
  `contracts/RiskQuoteVerifier.sol` verifies
- `service/`: the request-a-quote pipeline
  (`quoting.py`/`signing_service.py`) and a small FastAPI service
  (`app.py`) exposing it over HTTP for `apps/web` to call, plus
  `analytics.py` (read-only orchestration over already-tested functions
  above - no new quant logic - exposing GARCH diagnostics, the
  volatility-model comparison, the VaR/ES Kupiec backtest, and the
  FHS-vs-GBM tail comparison as `GET /v1/models/garch`,
  `/v1/risk/snapshot`, `/v1/validation/volatility`,
  `/v1/validation/var-backtest`, `/v1/validation/tail-comparison` - what
  `apps/web`'s `/models` and `/risk` pages render) and `cache.py` (an
  in-process memoization for those, since the walk-forward backtests are
  real compute; no Redis).
- `pricing/` — unused scaffolding; collateral pricing policy lives in
  `policy/collateral.py` instead

**Status**: volatility modeling, VaR/ES/stress/
collateral policy/`RiskQuote`, and EIP-712 signing with cross-language tests are
implemented and tested against real ETH/USD data and the real deployed
`RiskEscrow`/`RiskQuoteVerifier` contracts. The analytics
endpoints above are consumed by the `apps/web` dashboard. See
`docs/methodology.md`, `docs/model_validation.md`, and `docs/security.md`
at the repo root, and `notebooks/01_returns_and_volatility.ipynb`,
`notebooks/02_garch_analysis.ipynb`, `notebooks/04_model_validation.ipynb`.
Regenerate the published validation numbers with
`scripts/export_validation_report.py`.

## Setup

```bash
cd quant
python3.12 -m venv .venv   # 3.12 preferred over very new interpreters for wheel availability
source .venv/bin/activate
pip install -e ".[dev,notebook,service]"
```

## Running

```bash
# full pipeline: fetch data -> quality checks -> fit GARCH -> save state
# -> simulate online updates -> out-of-sample validation
python scripts/run_pipeline.py

# risk engine -> RiskQuote -> on-chain field mapping, across
# all supported settlement horizons
python scripts/run_risk_pipeline.py

# the risk-oracle HTTP service (requires RISK_ORACLE_PRIVATE_KEY; see
# docs/security.md). apps/web's /api/quote/request calls this.
export RISK_ORACLE_PRIVATE_KEY=0x...
.venv/bin/uvicorn askgene_quant.service.app:app --port 8001

# tests (set ASKGENE_PYTHON for contracts/test/pythonRiskQuoteIntegration.test.js
# if this venv isn't at quant/.venv)
pytest
```

Market data is cached under `data_cache/` and model state under
`model_state/` (both gitignored — regenerated by running the pipeline;
not committed since they're fetched/derived, not source).
